# NEXUS PRO v6 — Cloud Hosting Platform

منصة استضافة حقيقية لتطبيقات Python و Node.js و المواقع الساكنة، مع لوحة أدمن كاملة وبوت Telegram مربوط بنفس المحرك (54 أمر).

## الجديد في v6

- **لوحة المستخدم مقسّمة فعليًا** إلى 3 أقسام منفصلة تمامًا (الرئيسية / خوادمي / إنشاء خادم) — كل قسم له مكانه، تدخل خادم وتخرج وتدخل تاني بدون ما تفقد مكانك.
- **حسابات مؤقتة (Trial)**: الأدمن أو البوت ينشئ حساب بعدد سيرفرات محدود ومدة زمنية محددة (بالساعة). بعد انتهاء المدة يُغلق الحساب ويتوقف كل سيرفراته تلقائيًا، والمستخدم يشوف رسالة واضحة "انتهى اشتراك حسابك أو الوقت المحدد له" عند محاولة الدخول.
- **Impersonation (الدخول كمستخدم)**: الأدمن يقدر يدخل حساب أي مستخدم من لوحة الأدمن (زر "👁️ دخول كـ")، يشوف خوادمه وملفاته وconsole بالضبط زي ما يشوفها هو، ثم يرجع لحسابه بزر واحد — كل عملية Impersonation مسجّلة في `audit_log`.
- **دومين خاص لكل سيرفر** + دومين أساسي للمنصة (Base Domain) من إعدادات الأدمن — يحفظ الاسم فقط، والـDNS/SSL لازم تُضبط يدويًا (موضّح بوضوح في الواجهة، مافيش وهم).
- **رسالة واضحة عند خطأ اسم الملف**: لو حددت `bot.py` كملف تشغيل ورفعت ملف باسم مختلف، الـConsole يقولك بالعربي "الملف bot.py غير موجود" بدل ما يفشل بصمت.
- **بانر نجاح بصري كبير** (اسم NEXUS + علامة ✓) يظهر تلقائيًا في الـConsole لو السيرفر اشتغل بدون أخطاء.
- **إدارة كاملة للسيرفر من إعداداته**: تغيير الاسم، تغيير ملف التشغيل، تفعيل/إلغاء إعادة التشغيل التلقائي، ربط/حذف الدومين، وحذف السيرفر نهائيًا — كل ده من تبويب Settings في صفحة السيرفر (منفصل عن اسم الملف تمامًا).
- **إدارة ملفات أقوى**: رفع، تحميل (Download)، إعادة تسمية (Rename)، حذف — بدون أي نافذة `confirm()`/`prompt()` قديمة من المتصفح؛ كل التأكيدات من نوافذ مصممة داخل النظام نفسه.
- **صفحة دخول بتصميم مختلف تمامًا**: Matrix-rain خلفية متحركة، عنوان Glitch أحمر/سماوي، Scanlines، بدون أي مكتبة خارجية.
- **تشديد أمني إضافي**: بيئة مُصفّاة تمامًا لكل عملية مستخدم (لا أسرار منصة إطلاقًا)، حدود RAM/عمليات/ملفات حقيقية لكل عملية، حماية Zip Bomb، Rate Limiting لتسجيل الدخول.

## ⚠️ ملاحظة نشر مهمة

**Netlify لا يصلح لهذا المشروع.** Netlify مخصصة للمواقع الساكنة والـ Serverless Functions قصيرة العمر فقط،
ولا تدعم تشغيل عملية خادم دائمة (FastAPI) تدير Processes وSQLite وWebSocket. استخدم **Railway** (موصى به) أو
أي VPS/Docker host بدلاً من ذلك.

## البنية (كلها ملفات مسطحة، بدون مجلدات فرعية للكود)

| الملف | الوظيفة |
|---|---|
| `db.py` | القاعدة (Schema + هيلبرز) — مصدر واحد يشاركه app.py و bot.py |
| `auth.py` | تشفير كلمات المرور، الجلسات، صلاحيات الأدوار (RBAC) |
| `process_manager.py` | محرك الاستضافة الحقيقي: Port Manager، تثبيت Dependencies، تشغيل/إيقاف Processes، مراقبة الموارد عبر psutil |
| `plans.py` | نظام الخطط Free/Paid/VIP، فحص الحدود، جدولة انتهاء الصلاحية |
| `app.py` | تطبيق FastAPI — كل الـ Routes (مستخدم + أدمن + بوت) |
| `bot.py` | بوت Telegram — يتصل بنفس الـ API، ليس بقاعدة بيانات منفصلة |
| `login.html` / `dashboard.html` / `editor.html` / `admin.html` | كل صفحة **مستقلة بالكامل**: الـ CSS والـ JavaScript مدمجان داخل نفس الملف (`<style>`/`<script>` inline) — لا يوجد `style.css` أو `app.js` منفصل، ولا اعتماد على `/static`. كل صفحة لها لون Accent خاص بها (Servers=أزرق، Admin=أحمر) لكن بنفس نظام الـ CSS Variables فتبقى متناسقة. |

## التثبيت محليًا

```bash
pip install -r requirements.txt
cp .env.example .env   # ثم عدّل القيم
export $(cat .env | xargs)
uvicorn app:app --reload
```

افتح http://127.0.0.1:8000 — أول تشغيل ينشئ حساب الأدمن تلقائيًا باسم المستخدم المحدد في
`NEXUS_ADMIN_USER` وكلمة المرور من `NEXUS_ADMIN_PASSWORD` (لو لم تحددها، سيطبع النظام كلمة مرور
مؤقتة في اللوج — **يجب تحديدها يدويًا في الإنتاج**).

## متغيرات البيئة (.env.example)

- `NEXUS_SECRET` — مفتاح تشفير الجلسات (أنشئه بـ `secrets.token_hex(48)`)
- `NEXUS_ADMIN_USER` / `NEXUS_ADMIN_PASSWORD` — بيانات دخول الأدمن الأول
- `BOT_TOKEN` — توكن بوت Telegram (من BotFather)
- `NEXUS_API_URL` — رابط الـ API الذي يتصل به البوت
- `NEXUS_BOT_API_KEY` — مفتاح سري منفصل يستخدمه البوت فقط للوصول إلى `/api/bot/*`
- `TELEGRAM_ADMIN_IDS` — أرقام Telegram ID المسموح لها باستخدام البوت (مفصولة بفاصلة)

لا تضع أي قيمة حقيقية داخل `.env.example` نفسه — هو قالب فقط.

## النشر على Railway

1. اربط المستودع بـ Railway (أو ارفع الملفات مباشرة).
2. أضف متغيرات البيئة أعلاه من تبويب Variables.
3. Railway يكتشف `railway.json` و`Procfile` تلقائيًا ويشغّل:
   `uvicorn app:app --host 0.0.0.0 --port $PORT`
4. (اختياري) شغّل `bot.py` كخدمة (Service) منفصلة على نفس مشروع Railway، بنفس متغيرات البيئة.

## تشغيل بوت Telegram

```bash
python bot.py
```

يعمل كعملية مستقلة عن الويب، لكنه يتحكم بنفس محرك الاستضافة عبر HTTP API محمي بـ `NEXUS_BOT_API_KEY` —
أي تغيير من البوت (تشغيل/إيقاف سيرفر، تغيير خطة، حظر مستخدم، بث إعلان) ينعكس فورًا في لوحة الويب.

**54 أمر حقيقي** مقسّمة كالتالي (التفاصيل الكاملة داخل البوت بأمر `/help`):
- **مستخدمون (12):** users, userinfo, adduser, deluser, enableuser, disableuser, setrole, setplan, resetpass, recentusers, addtrial, searchuser
- **سيرفرات (22):** servers, serverinfo, addserver, delserver, startserver, stopserver, restartserver, suspendserver, unsuspendserver, serverlogs, setenv, recentservers, ports, killall, searchserver, files, readfile, setdomain, basedomain, setentry, rename, autorestart_on/off
- **خطط (3):** plans, planinfo, editplan
- **نظام (10):** system, stats, audit, settings, setsetting, maintenance_on, maintenance_off, broadcast, ping, version
- **إدارة أدمنز البوت (3):** listadmins, addadmin, removeadmin — قائمة معرّفات Telegram المصرح لها باستخدام البوت، محفوظة في قاعدة البيانات فتنجو من إعادة تشغيل البوت
- **أساسية (3):** start, help, whoami

كل أمر يمرّ عبر `X-Bot-Token`، وكل عملية حساسة تُسجَّل في `audit_log` بنفس طريقة تسجيل عمليات لوحة الويب.

## الأمان — ما هو مطبق فعليًا وما هي حدوده

- **لا تسجيل عام**: تسجيل الدخول فقط. الحسابات تُنشأ من لوحة الأدمن أو بوت Telegram حصرًا — لا يوجد `/api/auth/register` مكشوف على الإطلاق.
- كلمات المرور مشفّرة بـ bcrypt، لا نص صريح أبدًا، لا في الكود ولا في القاعدة.
- الجلسات موقّعة (Signed Cookies) عبر `itsdangerous`، ومحدودة الصلاحيات (Rate Limiting على تسجيل الدخول: 6 محاولات كل 5 دقائق لكل مستخدم/IP).
- صلاحيات أدوار (RBAC): owner / admin / moderator / support / user.
- **عزل الأسرار عن كود المستخدمين**: أي Process يشغّله مستخدم (أو حتى `pip install` / `npm install`) يحصل على بيئة (env) مُصفّاة تمامًا — لا يرى `NEXUS_SECRET` ولا `NEXUS_ADMIN_PASSWORD` ولا `NEXUS_BOT_API_KEY` ولا `BOT_TOKEN` إطلاقًا، فقط متغيراته الخاصة + PATH الأساسي.
- **حدود موارد حقيقية على كل Process** (عبر `resource.setrlimit`): سقف ذاكرة (RAM) مأخوذ من خطة المستخدم فعليًا، سقف عدد الملفات المفتوحة، سقف عدد العمليات الفرعية — يمنع مستخدمًا واحدًا من استهلاك كل موارد الجهاز.
- **حماية رفع الملفات**: حد أقصى 50MB للملف، وحماية من Zip Bomb (سقف على عدد الملفات وحجمها بعد فك الضغط)، وفحص كل مسار داخل أي ZIP يمنعه من الكتابة خارج مجلد السيرفر حتى لو استخدم `../` أو مسارات مطلقة.
- حماية من Path Traversal في File Manager (`safe_path`) — مطبّقة على القراءة والكتابة والحذف والرفع كلها.
- كل عملية أدمن حساسة (من الويب أو من البوت) تُسجَّل في `audit_log`.
- **العزل الحقيقي محدود بحدود بيئة الاستضافة**: هذا الإصدار يشغّل كود المستخدمين كـ Processes منفصلة (subprocess) بحدود موارد ومتغيرات بيئة مُصفّاة، وليس Containers معزولة بالكامل على مستوى نظام الملفات. يعني هذا أن كود مستخدم خبيث لا يستطيع الوصول للأسرار أو استهلاك كل الموارد، لكنه نظريًا قادر على قراءة ملفات أخرى على نفس الجهاز لو كانت الصلاحيات تسمح بذلك على مستوى نظام التشغيل. لعزل نظام ملفات كامل (Docker-per-server)، البنية في `process_manager.py` مصممة بحيث يمكن استبدال `start_server_process` بتشغيل Container بدلاً من Process مباشر، لكن هذا يتطلب بيئة تدعم Docker-in-Docker وهو خارج نطاق هذا الإصدار — لا نزعم عزلاً كاملاً غير موجود فعليًا.

## بيانات الأدمن الأول

اسم المستخدم `flixflixx11@` يُنشأ تلقائيًا عند أول تشغيل، لكن **كلمة المرور ليست مكتوبة في أي ملف من ملفات المشروع** —
يجب أن تحددها أنت بنفسك عبر متغير البيئة `NEXUS_ADMIN_PASSWORD` (في Railway Variables أو ملف `.env` محلي).
لو نسيت تحديدها، النظام يولّد كلمة مرور عشوائية مؤقتة ويطبعها في اللوج مرة واحدة عند أول تشغيل — يفضّل دائمًا تحديدها يدويًا بنفسك بدل الاعتماد على ذلك.


## الخطط (Plans)

مركزية بالكامل في جدول `plans` — Free / Paid / VIP بحدود قابلة للتعديل من لوحة الأدمن (عدد السيرفرات،
RAM، CPU، التخزين، مدة الصلاحية). لا توجد أي أرقام Hardcoded داخل الكود.
